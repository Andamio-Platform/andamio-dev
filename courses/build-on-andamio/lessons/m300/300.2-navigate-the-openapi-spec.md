# Navigate the Andamio API spec

## Before we start

The Andamio API has dozens of endpoints. You don't need to remember them — you need to find the one you want in under a minute. The OpenAPI spec is the map.

## Where the spec lives

`specs/andamio-api.yaml` in the `andamio-dev` repository. If you have the plugin installed, it's on disk. Otherwise, it's in the public repo at [github.com/Andamio-Platform/andamio-dev](https://github.com/Andamio-Platform/andamio-dev).

This is the **public contract** — the operations available to you as an integrator. It is not every route the server has. Administrative and internal operations are deliberately left out, so if you go looking for something you've heard mentioned and it isn't here, that's the reason.

Don't read it top to bottom. Jump in, find what you need, jump out.

## Three ways to find an endpoint

**grep.** Fastest when you know part of the path. Every endpoint starts with `/v2/`:

```bash
grep -n "/v2/course/student" specs/andamio-api.yaml
```

Path declarations sit under the `paths:` key — look for lines like `  /v2/course/student/credentials/list:`.

**IDE search.** Fuzzy-search for keywords ("credentials," "enrollment," "task," "assess"). Better when you don't remember the exact path fragment.

**Spec viewer.** Swagger UI, Redoc, Stoplight Studio, or the VS Code OpenAPI extension. Worth it for serious exploration; overkill for one-off lookups.

## Reading an endpoint entry

The spec is **Swagger 2.0**, not OpenAPI 3. That matters for two things you'll see constantly: schema refs point at `#/definitions/...` (not `#/components/schemas/...`), and auth is declared in a `security:` block (not as `$ref`'d header parameters).

```yaml
/v2/course/student/credentials/list:
  post:
    tags:
    - Course/Student
    summary: List my credentials
    operationId: v2-merged-course-student-credentials-list
    produces:
    - application/json
    security:
    - ApiKeyAuth: []
      BearerAuth: []
    responses:
      '200':
        description: OK
        schema:
          $ref: '#/definitions/StudentCredentialsResponse'
      '401':
        description: Unauthorized
        schema:
          $ref: '#/definitions/ErrorResponse'
```

| Part | What to read | Notes |
|------|-------------|-------|
| **Path** | `/v2/course/student/credentials/list` | Append it to the host **and the spec's `basePath: /api`** — the full URL is `https://preprod.api.andamio.io/api/v2/course/student/credentials/list` |
| **Method** | `post:` | Even reads can be POST in Andamio (request body filtering). Don't assume reads are GETs. |
| **Summary** | One-line description | Usually accurate enough to confirm the endpoint fits your task |
| **Security** | Which credentials the route needs | Both names listed under a single `-` entry means **both** are required: `ApiKeyAuth` (`X-API-Key`) plus `BearerAuth` (`Authorization: Bearer <jwt>`). Two separate `-` entries would mean either one suffices. |
| **Responses** | `'200'` schema via `$ref` | Follow the JSON Pointer to `#/definitions/...` for the full shape |

`$ref` references point to schema definitions under the top-level `definitions:` key. Most editors and spec viewers follow them automatically.

Forgetting the `/api` basePath is the most common reason a hand-built URL 404s.

## A worked lookup

Task: find the endpoint that lists courses.

1. `grep -n "courses/list" specs/andamio-api.yaml`
2. Several paths match — `/v2/course/user/courses/list` is the one that isn't scoped to a role you hold.
3. Method: GET. Auth: `ApiKeyAuth`. No parameters. Response: `MergedCoursesResponse`.
4. Follow the `$ref` to `MergedCoursesResponse` to see the response shape.

Under a minute with grep. Under five with a spec viewer.
